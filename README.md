# MintOS26 26.5.013.0 — MintDE 2.3.0

**MintOS26** is the operating system and kernel. **MintDE — Mint Desktop Environment** is its native ring-3 desktop environment, independently versioned as **MintDE 2.3.0**. The firmware-mediated desktop is referred to as **UEFI Desktop**.

The startup selector defaults to UEFI Desktop (Enter/1 or a three-second timeout). Press 2/M to request the experimental MintDE native handoff. MintDE calls `ExitBootServices`; this handoff is one-way until reset, so keep EFI enabled and retain UEFI Desktop as the recovery path.

## 26.5.013.0 / MintDE 2.3.0 — files that stay (MintFS)

MintOS has its own read/write filesystem, **MintFS**. It is copy-on-write and checksummed like APFS, so a power cut leaves the last saved state rather than a damaged disk.

- **Setting up a disk:** Disk Utility turns a blank disk into a **MintOS disk** ("MintOS HD") with a macOS-style layout: `/Applications`, `/Users/mintos/Documents`, Downloads, and so on. The disk mounts at every boot.
- **Files** works like Finder, with Favorites, New Folder, Rename, Duplicate and Trash.
- **Notes** saves to `~/Documents`.
- **Terminal** has `ls`, `cd`, `mkdir`, `rm`, `mv`, `cp`, `cat`, `echo > file` and `df`.
- **Write safety:** MintOS writes only to disks it initialized itself, through a guard in the block layer. Every other disk stays read-only.
- **Trying it:** in QEMU, run `tools/run_qemu.sh --mintos-disk` (see `TESTING.md`).

## 26.5.012.0 / MintDE 2.2.0 — secure web (HTTPS)

MintOS has its own TLS 1.3 client and certificate validation against Mozilla's list of trusted authorities. The Web app opens HTTPS sites with a padlock in the address bar, and certificate problems stop the page with an explanation. Search uses DuckDuckGo. `curl https://…` works in Terminal. Servers that only speak TLS 1.2 are not supported yet.

## 26.5.011.0 / MintDE 2.1.0 — USB, networking and the web

- **USB input works natively.** A polled xHCI driver supports USB keyboards, mice and tablets on the computer's own ports (no hubs yet). This matters on machines without PS/2, such as the Dell OptiPlex 7040.
- **MintOS is on the Internet.**
  - **Network drivers:** an Intel E1000-family driver covers the adapters that QEMU, VirtualBox, VMware and Hyper-V emulate, plus experimental Intel I217/I218/I219 support.
  - **Network stack:** MintOS's own IPv4 stack with DHCP, DNS, ping and TCP.
  - **Automatic connection:** in a virtual machine MintDE connects on its own; open **Network** to see the address.
- **Web**, a small browser for HTTP pages: links, history, search through wiby.me, and readable text layout. Secure (HTTPS) sites need TLS, which is not implemented yet.
- **Terminal:** `net up`, `ifconfig`, `ping <host>`, `nslookup <host>`, `curl http://…` and `usb`.

## MintDE 2.0.0 — a macOS-style desktop

MintDE 2 is a new desktop rendered in user space on a shared display canvas:

- Multiple windows with traffic lights, shadows, drag, resize, zoom and minimize.
- A translucent menu bar with menus, Control Center, Spotlight (⌘Space) and a real clock.
- A glass Dock with tooltips and running-app dots.
- Launchpad, the ⌘Tab switcher, and Light, Dark and Auto appearance with accent colours.
- Redesigned Files, Settings, Terminal, Notes, System Monitor, Storage & Logs, Hardware & Drivers, Network and Disk Utility windows, plus a new Calculator.

The Windows key acts as Command. Artwork (the "Mint Waves" wallpapers, icons and pointers) is original and generated by scripts in `tools/`. The UI font is Inter (SIL Open Font License, `docs/INTER_FONT_LICENSE.txt`).

## 26.5.009.0 highlights — real hardware and VMs

- **Any display mode up to 4K.** The native kernel no longer halts when the firmware's GOP mode is above 1920x1080 or has a padded stride. Display buffers are sized from the actual mode, and the framebuffer is mapped write-combining through the PAT, which should make presenting to a real GPU much faster (not yet measured on hardware).
- **Pointer fix.** PS/2 mouse deltas are decoded as 9-bit signed values, so fast movements no longer reverse direction. A fixed-point acceleration curve gives precise slow movement.
- **Shut Down and Restart.** The MintDE menu has Restart… and Shut Down… with a macOS-style confirmation alert, using ACPI S5 and FADT/0xCF9/8042 reset. Terminal adds `power`, `shutdown` and `restart`.
- **Dell "RAID On" SATA.** Intel RAID-mode controllers are read through their AHCI interface after register validation.
- **QEMU on Linux and macOS:** `make run` (or `tools/run_qemu.sh`). See `docs/REAL-HARDWARE.md` for the Dell OptiPlex 7040 guide.

Validated live on QEMU 11.1 q35/OVMF: native boot, ACPI power-off, restart and fast pointer motion. Not yet validated in VirtualBox or on physical hardware.

## Earlier release highlights

- MintDE begins on a clean workspace; Launchpad remains in the dock. The About MintOS26 and About MintDE screens are separate, and each has a changelog button hidden until requested.
- Rounded alpha-blended surfaces with backdrop sampling/specular edges, per-app PNG icon assets, functional mouse-driven Settings dropdowns and menu dropdowns, a software arrow cursor without the duplicate kernel overlay, and an initial resize-grip implementation.
- Settings includes General, Appearance, Displays, Input, Storage and Privacy categories.
- Files shows Session (RAM) separately from every registered read-only FAT16 volume, with explicit volume selection, directory navigation and bounded text preview.
- Standard FAT16 volumes can be mounted without MintOS-specific seed files. A versioned VFS mount table publishes `/session` and independent `/Volumes/<device>` mount paths; up to eight mounted volumes can be registered for Files. The block layer now tracks per-device generic read results and denied write attempts.
- System Monitor, Storage & Logs, Hardware & Drivers and a bounded diagnostic Terminal provide honest service/hardware status. Terminal exposes `pci`, `resources`, `drivers`, `mounts`, `io`, `logs`, `cpu`, `use sda/sdb`, and volume-aware `ls`/`cat`. The experimental Intel 82540EM path is read-only-detected at boot; `net start` explicitly enables its bounded DMA driver, and `net test` now uses the TCVR internal loopback-buffer path required by VirtualBox's emulated 82540EM and captures the actual submitted TX descriptor plus RX descriptor state. Loopback completion remains pending live VM validation; no IP stack is included.
- AHCI uses READ/WRITE DMA EXT and FLUSH CACHE EXT when a device advertises LBA48. Disk Utility only initializes an explicitly confirmed blank disposable disk; generic block writes remain denied.

## Storage truth

A COM1 log from the 26.5.001.0 VM showed one valid 512 MiB FAT16 developer disk mounted read-only, with the developer ID and `55 AA` MBR signature, while a second detected disk returned repeatable zero-filled LBA 0 and was correctly rejected as blank. The same log contains a formatter error for one operation followed later by successful read-only mount entries. Treat these as separate events and preserve the full log when testing.

**MintOS writes only to MintOS disks:** GPT disks with a MintFS partition that MintOS initialized itself. Those writes go through a block-layer grant covering just that partition. FAT16 and all other disks remain read-only. Without a MintOS disk, Notes stay in session RAM. Settings are always session-only for now. The blank-disk initializer is deliberately narrow and destructive; use only a disposable data disk in a snapshot, after confirming model, serial and capacity. Mount success is not proof of durable writes.

## Build and host checks

Requirements: clang, `lld-link`, `ld.lld`, GNU make, Python 3, and Pillow for concept previews. On macOS: `brew install lld qemu binutils`; Apple clang builds the OS unchanged.

```sh
make clean all
make check
make preview
```

The build produces the EFI application, native kernel ELF, ring-3 programs, ESP, GPT UEFI disk, raw developer image, populated dynamic/fixed VDIs, blank dynamic VDI and UEFI ISO. Host tests include source checks, production parser/formatter tests, a two-volume/generic-FAT16 test, pixel-level alpha blending and artifact validation.

Host tests do not emulate live AHCI/E1000 DMA or prove MintDE runtime behavior. On Apple Silicon, run them with `PATH="$PWD/tools/macos-host:/opt/homebrew/opt/binutils/bin:$PATH" make check`. One test (`test_context_switch.py`) links ELF-format kernel assembly into a host binary and only runs on a Linux host.

`make run` boots the GPT image in QEMU/OVMF (q35, AHCI, e1000, COM1 to `build/com1-qemu.log`; disks are `snapshot=on`).

### E1000 loopback troubleshooting

Boot performs read-only E1000 detection only. In a disposable VirtualBox snapshot, run `net status`, `net start`, `net test`, then `net status`. If loopback fails, the new COM1 record includes the failing phase and a bounded snapshot of the E1000 MAC/PHY registers and descriptor completion bits. It still sends no external packets.

Terminal command history is displayed with `root#mintos >` and colored separately from command output.

### 26.5.008.0 E1000 test sequence

MintDE Terminal displays each entered line using the distinct `root#mintos >` prompt. For the opt-in Intel 82540EM diagnostic, use a disposable VirtualBox snapshot and run:

```text
root#mintos > net status
root#mintos > net start
root#mintos > net test
root#mintos > net status
```

Boot only performs read-only PCI detection. `net start` enables the experimental bounded-polling RX/TX rings and DMA; `net test` sends only an internal loopback probe. If it fails, preserve the COM1 `loopback FAIL stage=...` register snapshot and the Terminal `Loopback stage/error` output. Do not interpret host tests as proof of guest DMA. No TCP/IP stack or external packet-send service is included.
